## Findings, ranked by severity

1. **High — Refresh ends a solo game.** [server/game.py:132](server/game.py:132), [server/app.py:105](server/app.py:105): When the only human plays against bots and refreshes, the old socket disconnects. `disconnect()` immediately sets the phase to `over`, even though the reconnect token still holds the seat. Reconnecting shows “No one survived” and cannot resume the match. **Fix:** keep the game resumable during a reconnect grace period; stop bot activity during the absence and end the game only if that period expires.

2. **Medium — A reconnecting human can lose their turn to autoplay.** [server/game.py:270](server/game.py:270), [server/bots.py:85](server/bots.py:85), [server/app.py:80](server/app.py:80): If a disconnected player’s turn begins, a bot task is scheduled. Reconnecting marks the player connected but leaves that task running; it can submit while the human is typing. **Fix:** cancel the pending autoplay task on reconnect and have it check `player.connected` before submitting.

3. **Medium — Disconnecting during an active turn gets no bot cover.** [server/game.py:125](server/game.py:125), [server/game.py:270](server/game.py:270): With another human still connected, disconnect the current player after their turn starts. Autoplay is scheduled only at turn start, so this player times out and loses a life. **Fix:** when the current player disconnects, schedule autoplay for the current turn.

4. **Medium — An old grace timer can drop a newly disconnected player early.** [server/app.py:111](server/app.py:111), [server/game.py:138](server/game.py:138): Disconnect, reconnect after 19 seconds, then disconnect again. The first 20 second cleanup sees `connected=False` and removes the lobby seat after only about one second of the second absence; it can also transfer host status. **Fix:** cancel earlier cleanup tasks or attach a disconnect generation/deadline and verify it before dropping the player.

5. **Medium — Malformed WebSocket fields escape the error handler.** [server/app.py:77](server/app.py:77), [server/app.py:95](server/app.py:95), [server/game.py:154](server/game.py:154): A host sending `{"type":"settings","settings":{"turnSeconds":"bad"}}` raises `ValueError`; the socket handler exits and disconnects the host. In a solo room, that also ends the game. A non-object hello such as `[]` similarly raises at `.get()`. **Fix:** validate message shape, field types, ranges, and frame size before handling; return a protocol error for bad input.

6. **Medium — Bot computation can make an expired turn succeed.** [server/bots.py:85](server/bots.py:85), [server/game.py:230](server/game.py:230), [server/game.py:195](server/game.py:195): The bot holds `room.lock` while computing in a thread. If computation runs past the deadline, the timeout waits for that lock, and the bot can submit without a deadline check. **Fix:** compute outside the lock, then recheck turn identity and deadline under it; enforce the deadline in `submit()`.

7. **Medium — A host can reset a live match through the protocol.** [server/app.py:160](server/app.py:160), [server/game.py:281](server/game.py:281): Although the UI offers “Back to lobby” after a game, a host can send `{"type":"lobby"}` while playing. This cancels the turn and discards the match immediately. **Fix:** require phase `over` in `back_to_lobby()` if that is the intended game flow.

8. **Medium — Stale client connections can rejoin or overwrite a newer session.** [web/assets/app.js:94](web/assets/app.js:94), [web/assets/app.js:101](web/assets/app.js:101): A socket close schedules a reconnect; clicking Leave before its timer fires still reconnects to the old room. Rapidly initiating two connections also lets messages from the first socket replace the second room’s state and store a token under the wrong code. **Fix:** cancel pending retries on leave/new connection, close the previous socket, and ignore events whose socket is no longer `S.ws`.

9. **Low — Idle room reaping strands connected lobby clients.** [server/app.py:170](server/app.py:170): After three hours without a broadcast, the reaper deletes a room even if sockets remain connected. Their handlers still process actions against the old `Room`, but broadcasts have no socket registry, so the UI stops updating. **Fix:** retain rooms with connected sockets or close those sockets when reaping them.

I found no confirmed client XSS path: player names and move strings used in HTML are escaped; bot difficulty labels come from the server’s fixed allowlist. No files were changed.
